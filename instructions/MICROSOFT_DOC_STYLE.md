# Microsoft Documentation Style

## Use

Use this instruction for all deliverables that become project documentation.

## Rules

- Use direct second-person only in task procedures.
- Prefer active voice.
- Use short, precise headings.
- Define terms before using them.
- Use tables for matrices and option comparisons.
- Use ordered steps for procedures.
- Use `Note`, `Important`, and `Warning` blocks only when they add operational value.
- Avoid marketing language.
- Avoid unexplained acronyms.
- Keep terminology consistent with the Andromeda lexicon.

## Standard page structure

1. Title.
2. Purpose.
3. Scope.
4. Concepts.
5. Requirements.
6. Procedure or design.
7. Validation.
8. Risks.
9. Related decisions.
