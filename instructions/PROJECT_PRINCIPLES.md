# Project Principles

## Purpose

Apply the Andromeda doctrine to all AI-assisted work.

## Rules

1. Preserve the contract-first, type-first, transaction-first, recovery-first, observability-first model.
2. Treat SRPL as a strict relational procedure language, not renamed SQL.
3. Treat QUIC as the transport and Protobuf as contract serialization, not gRPC.
4. Require deterministic reasoning for runtime behavior.
5. Require a recovery story for any persistent mutation.
6. Reject any optimization that cannot be measured, explained, bounded, versioned, and disabled.
7. Separate enterprise-grade core paths from experimental research paths.

## Required output style

Use American English. Use Microsoft documentation style: clear headings, short paragraphs, procedural steps, tables when
useful, and explicit warnings.
