# Skill Authoring Standard

## Purpose

Define how Andromeda skills are written.

## Rules

- One skill equals one capability.
- The description must include when to use the skill.
- Keep `SKILL.md` concise.
- Move long references to support files.
- Restrict tools when possible.
- Include version history.
- Include refusal or escalation criteria.
- Include a standard output contract.

## Anti-patterns

- A skill that acts as a full architect.
- A skill that contains an entire agent prompt.
- A vague description such as "database help".
- Hidden prerequisites.
- Tool permissions broader than necessary.
