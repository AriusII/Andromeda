# Fuzzing Layout

This directory contains the libFuzzer harnesses and deterministic seed corpus for Andromeda binary, parser, storage, protocol, and admission boundaries.

## Directory Contract

- `fuzz_targets/` contains one harness per bounded fuzz surface.
- `tests/fuzzing/targets.toml` is the authoritative target registry for harness name, source path, seed corpus directory, and generator.
- `generators/generate_seed_corpus.py` creates and verifies deterministic seed files.
- `tests/fuzzing/corpus/` contains committed deterministic seed inputs that improve first-run coverage.
- `tests/fuzzing/corpus/manifest.toml` records the expected seed files for each target.
- `artifacts/` is generated by fuzzing runs and is ignored by git.
- `target/` is Cargo build output and is ignored by git.

## Harness Policy

- Harnesses must reject malformed input without panicking.
- Harnesses must preserve the same invariants as the production boundary they exercise.
- WAL, page, frame, and ResultStream fuzzing must prefer round-trip, bounded-size, and no-panic properties over unbounded exploration.
- SRPL fuzzing must not introduce an ad hoc SQL application surface.
- QUIC admission fuzzing must keep security and replay decisions typed and explicit.
- Seed corpus generation must be deterministic and reproducible on Windows and CI.

## Commands

```powershell
python fuzz/generators/generate_seed_corpus.py --check
python fuzz/generators/generate_seed_corpus.py --ensure-only
```

When `cargo-fuzz` is installed, run individual harnesses from this directory:

```powershell
cargo fuzz run frame_codec_no_panic
cargo fuzz run storage_wal_record_roundtrip
cargo fuzz run quic_zero_rtt_admission
```

Use short local fuzz runs for development and longer scheduled jobs for release evidence. Do not commit files under `fuzz/artifacts/` or `fuzz/target/`.
