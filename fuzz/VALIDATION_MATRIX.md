# Fuzz and Golden Validation Matrix

## Purpose

Document the current readiness matrix for persisted-byte fuzzing and golden/vector validation across the WAL record frame codec, PageCodecV1, HeapPageV1, and BTreeNodeV1 surfaces.

## Scope

This matrix covers documentation status only. It records the current fuzz target, deterministic seed corpus, golden or vector coverage, and the remaining readiness item for each storage-critical surface.

## Non-goals

- Do not redefine the binary formats.
- Do not change fuzz harness behavior.
- Do not add, remove, or regenerate seed files.
- Do not replace crash/recovery validation with fuzz or golden evidence.

## Validation

Documentation claims in this file should stay traceable to:

- `fuzz/targets.toml`
- `fuzz/corpus/manifest.toml`
- `fuzz/generators/generate_seed_corpus.py`
- `fuzz/fuzz_targets/*.rs`
- `crates/andromeda-wal/tests/*` for pure WAL owner evidence
- `crates/andromeda-storage/tests/*`
- `crates/andromeda-storage/src/page_codec_v1/tests.rs`

For documentation-only edits, run:

```powershell
python fuzz/generators/generate_seed_corpus.py --check
cargo test -p andromeda-wal --tests
cargo check --manifest-path fuzz/Cargo.toml --bin wal_record_roundtrip --locked
```

For readiness promotion, add sustained fuzz run evidence for the specific owner surface being promoted. For FileWal, recovery, page, manifest, or visibility promotion, add the targeted storage tests and crash/recovery evidence for the integration surface as well.

## Troubleshooting

If a target, corpus directory, or seed list drifts, treat `fuzz/targets.toml` and `fuzz/corpus/manifest.toml` as the authoritative registry pair and update this matrix only after the generator check passes.

If a golden/vector suite moves, keep this file pointed at the stable owning test module rather than duplicating the vector bytes here.
