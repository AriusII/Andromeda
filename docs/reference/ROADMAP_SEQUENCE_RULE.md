# Roadmap sequence rule

> **Status:** Reference  
> **Audience:** Documentation authors and reviewers

## In this article

- Define the reference topic.
- Preserve consistency across the documentation set.

## Purpose

Explains how to write a technical roadmap with sequencing language and no calendar commitments.

## Rules

- Use stable terms from `project/GLOSSARY.md`.
- Use doctrine from `project/ANDROMEDA_DOCTRINE.md`.
- Use specifications for normative technical behavior.
- Use ADRs for decisions.
- Use runbooks for operations.
- Use roadmap files for sequence only, not schedule.

## Review checklist

```text
One H1 only
American English
No calendar promises in roadmap files
No hidden SQL application surface
No contradiction with WAL-first doctrine
No GPU participation in C5 paths
No native Rust layout persistence
No unaudited security decision
```
